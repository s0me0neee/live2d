# Plan: TOML config + always-on-top overlay window

## Context
Config currently lives in two hand-written TS files: `src/config.ts`
(model-independent tuning) and `src/model-config.ts` (per-model: paths, scale,
hair/cloth param prefixes). We want the editable source of truth to be TOML
instead — `config.toml` for the model-independent knobs and
`config_<model>.toml` for each model — so non-code edits don't touch `.ts`.
Separately, the app should behave like a desktop avatar overlay: a transparent,
frameless, always-on-top window.

The repo already has a "Rust generates TS on launch" convention:
`src-tauri/src/build_exp_keys.rs` scans the model dir and emits
`src/expressions/generated.ts`, and `main.rs` runs it at startup. We follow the
same pattern for config so the frontend keeps fully-typed `config` /
`modelConfig` objects and zero new runtime dependency.

---

## Part 1 — TOML config (Rust generates the TS)

### File layout (repo root)
- `config.toml` — model-independent. Has a `model = "ariu"` selector key.
- `config_ariu.toml` — model-dependent (one per model; selected by the key above).

### `config.toml` (mirrors today's `config.ts` shape exactly)
```toml
model = "ariu"          # selects config_<model>.toml (stripped from generated TS)

mirror = true
smoothing = 0.6
headGain = 1.5
headClampDeg = 90
bodyFollow = 0.333333
breath = 0.5
blinkGain = 1.4
detectFps = 60

[jaw]
deadzone = 0.004
curve = 0.23
gain = 1.1

[camera]
width = 640
height = 480

[physics]
windEnabled = false
gust = 0.05
gustHz = 0.5
springiness = 1.02

[physics.wind]
x = 0.03
y = -0.03
```

### `config_ariu.toml` (mirrors today's `model-config.ts`)
```toml
dir = "/model/ariu/"
file = "ariu.model3.json"
scale = 0.2

[hair]
prefix = "ParamHair"
gain = 1.7

[clothes]
prefix = "Param_Angle_Rotation"
gain = 2.0
```

Keys are kept identical to the current TS so **no consumer changes** are needed
(`config.headGain`, `config.physics.wind.x`, `modelConfig.hair.prefix`, etc.).
TOML rule: all bare scalars must precede the first `[table]` — values above are
already ordered that way.

### New `src-tauri/src/build_config.rs`
Same structure/style as `build_exp_keys.rs`:
1. Read `config.toml`, parse with the `toml` crate into a `toml::Value` table.
2. Pull the `model` string, read `config_<model>.toml`.
3. Strip `model` from the independent table.
4. A small generic `toml::Value → TS literal` emitter (recursive: tables →
   `{ k: v, ... }`, arrays → `[...]`, strings quoted, bool/int/float verbatim).
5. Overwrite `src/config.ts` exporting `export const config = {…} as const;`
   and `src/model-config.ts` exporting `export const modelConfig = {…} as const;`,
   each with an `// AUTO-GENERATED by build_config.rs — edit the .toml instead` header.

Generic emission (vs. mirrored Rust structs) keeps the generator schema-agnostic,
so adding a knob means editing only the `.toml`.

### Wiring
- `src-tauri/Cargo.toml`: add `toml = "0.8"` (serde already present).
- `src-tauri/src/main.rs`: `mod build_config;` and call
  `build_config::generate().expect(...)` right before `build_keys()`.
- `src-tauri/src/lib.rs`: `mod build_config;` (compiled in lib crate like the
  existing one; `#![allow(dead_code)]` to silence the unused warning).
- Use the absolute-path macro style already in `build_exp_keys.rs` for the
  repo-root `.toml` locations and the `src/` output targets.

### Notes
- Because `main.rs` regenerates on every launch, editing a `.toml` then
  re-running `tauri dev` (or the binary) refreshes the generated TS; Vite HMR
  picks it up — same loop as expressions today.
- `src/config.ts` / `src/model-config.ts` become generated artifacts; the comment
  explanations for each knob move into the `.toml` files.
- Alternative considered (frontend fetches `.toml` from `public/` and parses at
  runtime): simpler, hot-reload without Rust, but loses static typing (parser
  returns `any`) and diverges from the repo's codegen convention. Not chosen.

## Part 2 — Always-on-top transparent overlay window

### `src-tauri/tauri.conf.json`
Add `macOSPrivateApi` (required for transparent windows on macOS) and overlay
flags to the window:
```json
"app": {
  "withGlobalTauri": true,
  "macOSPrivateApi": true,
  "windows": [
    {
      "title": "live2d",
      "width": 800,
      "height": 600,
      "transparent": true,
      "decorations": false,
      "alwaysOnTop": true,
      "shadow": false,
      "resizable": true,
      "skipTaskbar": true
    }
  ],
  "security": { "csp": null }
}
```

### Frontend transparency (`src/styles.css`)
The canvas is already `backgroundAlpha: 0`; make the page itself transparent and
full-bleed so the desktop shows through:
```css
html, body { margin: 0; height: 100%; background: transparent; overflow: hidden; }
#live2d { display: block; }
```

### Moving the frameless window (optional but recommended)
With `decorations: false` there's no title bar to drag. Add a small drag handle
(or reuse the FPS strip) marked `data-tauri-drag-region` so the overlay can be
repositioned. The expression panel already uses `pointer-events`, so keep the
drag region out of interactive controls.

### Out of scope (note for later)
- Click-through (`setIgnoreCursorEvents`) so clicks pass to apps behind — would
  disable the expression panel, so leave it as a future toggle.
- `macOSPrivateApi: true` makes the build ineligible for the Mac App Store
  (fine for personal/overlay use).

## Verification
1. `cargo build` in `src-tauri/` — confirms `toml` dep + `build_config.rs` compile.
2. Run `bun run tauri dev`:
   - On launch, `src/config.ts` + `src/model-config.ts` are regenerated from the
     TOMLs (check the AUTO-GENERATED header and that values match).
   - `bunx tsc --noEmit` stays clean (shape unchanged → no consumer breakage).
   - Edit e.g. `headGain` in `config.toml`, relaunch → tracking sensitivity changes.
   - Change `model` to a non-existent name → generator errors clearly (don't
     silently emit a half-config).
3. Window: appears frameless, floats above other apps (`alwaysOnTop`), desktop
   shows through the transparent areas around the model; model still renders and
   tracks. Drag handle repositions it.
